# 配置模板里、客户端「项目配置」弹窗**不显示**的配置项，每项写明为什么（GitHub#388 的补充）。
# Template keys the desktop client's project-settings dialog does not show, each with the reason.
#
# 模板（cavil-loop.config.example）里的每个配置项，要么登记在 scripts/config-fields.txt（窗口显示），
# 要么登记在这里，二选一；tests/config-fields-coverage.test.sh 检查这一点。daemon 和 project-config.sh
# 都不读这个文件，它只是让「这项不显示」成为一个写下来的决定，而不是忘了。
#
# 格式（| 分隔，两侧空白忽略；# 开头和空行跳过）：
#   KEY | 类别 | 原因
#
# 类别：
#   命令 / 钩子 / 令牌 / 网址 / 目录 / 名字   永远不进窗口（窗口能填它们就成了跑命令、读凭据的入口）
#   安装时生效                                安装脚本把它写进定时器之类的系统设置，窗口改了配置文件也不会生效（GitHub#556）
#
# 以前还有一个类别放「可以显示、只是还没核对默认值」的旧配置项（GitHub#550），已全部登记完、类别已删；
# 可以显示的配置项直接登记进 config-fields.txt，不再有「先放这里、以后再登记」这条路（tests/config-fields-coverage.test.sh 查）。
