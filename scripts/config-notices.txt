# 配置模板（cavil-loop.config.example）里每个配置项的「老项目缺这一行时要不要提示」登记表（GitHub#289）。
# Every key assigned in cavil-loop.config.example, and whether a project whose config lacks
# that line is told about it (GitHub#289).
#
# 为什么要有：自动升级把新代码带到老项目，却不会改项目自己的配置。新功能若是「配置里不写就关」、
# 模板里却是开的，老项目就一直关着，没有任何地方说一声（例：等前置标签，arkknights-tool#38）。
# daemon 每轮把本项目配置加载完后仍「未设置」的 notice 项列出来，写轮询日志，并按 CONFIG_NOTICE_ISSUE
# 在本项目仓库开一条提示 issue。写成空值（KEY=""）= 已决定不开，不算缺。
#
# 格式（| 分隔，两侧空白忽略；# 开头和空行跳过）：
#   KEY | notice | 出处 | 不开时写的值 | 给维护者看的一段说明（一行）
#   KEY | quiet  | 为什么不提示
#
# 判据：只有「模板里开、不写这一行就关」的功能项登记成 notice。不写时和模板值一样的、必填项、
# 示例值、权限参数一律 quiet。往模板里加新配置项时必须在这里登记，否则 tests/config-notice.test.sh 红。
#

ENABLE_CONCURRENT_WORK_HINT | notice | GigleAI/cavil-loop#340 | "" | 派工时告诉 worker 还有哪些条目在进行：worker 的提示词里多一段，列出其他带 `doing/agent`、复审标签、`pending/PR` 的打开条目（编号、标题、分支）和各分支已经改了哪些文件；worker 的方案或改动和它们有文件重叠时，必须在方案或交接评论里写出「和哪个条目、哪些文件」，由人决定先后。关着时 worker 只知道自己的条目，重叠要到交接时的冲突检查或对方合并后才发现。只在派工那一刻读（每次派工多 3–4 次只读调用），不需要建标签。这项设置原来叫 `CONCURRENT_WORK_HINT`，那个名字已不再生效，配置里写着它等于没写。
