# 客户端「项目配置」弹窗里出现的配置项登记表（GitHub#388）。scripts/project-config.sh 读它。
# The settings the desktop client's "项目配置" dialog shows (GitHub#388); read by scripts/project-config.sh.
#
# 只有登记在这里的配置项会被读出来给客户端，只有登记成 edit 的能被 project-config.sh set 改。
# 命令、钩子、令牌、网络地址、目录、项目名这几类**不登记**：窗口里能填它们，就等于窗口有了
# 在本机跑任意命令 / 读凭据的入口（tests/project-config.test.sh 按名单断言它们不在这里）。
#
# 格式（| 分隔，两侧空白忽略；# 开头和空行跳过）：
#   KEY | 分组标题 | 类型 | 不写这一行时 daemon 实际用的值 | edit / show | 名称 | 一句说明 [| 只显示的原因]
#
# 只显示的原因：show 行必填（这一行为什么不在窗口里改，窗口里写在这一行下面），edit 行不写。
# 只显示的行和可改的行放在同一个主题分组里（GitHub#554）。
#
# 类型：
#   agent          daemon 自带的 agent（scripts/drivers/ 下的 driver 名）
#   model          模型名；可以留空
#   int:MIN:MAX    整数，含两端。范围以使用它的代码实际接受的为准，按十进制数字比大小、不受位数限制：
#                  bash 拿去 [ -gt ] / $(( )) 的到 2^63-1（9223372036854775807，Linux 的 bash 5 和
#                  macOS 自带的 bash 3.2 一样），乘了数再比的取乘完不溢出的那个数。MAX 留空 = 代码不设上限
#                  （例：只有 Python 读的，或使用端自己处理大数的）；位数仍不超过 200，窗口送来的每个值都不超过
#                  200 个字符。范围要在 daemon 跑的每个平台上都成立：别把大数直接交给各平台上限不同的外部命令
#                  （macOS 的 head -n 只收到 2^31-1，GNU 的收到 2^64-1）
#   int:MIN:MAX:empty  同上，另外可以留空（留空是什么意思写在说明里，例：PREVIEW_PORT_MODULO 留空 = 不取余数）
#   bool:ON:OFF    开关；ON / OFF 是写进配置文件的那两个词
#   enum:a=说明,b=说明   几选一；= 后面是给人看的说明
#   label          标签名：空 = 这个功能关着（只用于 show）
#   text           原样显示的文字：标签名、标签列表、分支名、字段名这类不是开关的值（只用于 show）
#
# 「不写这一行时的值」一般也是「写成空值时」的值。两者不同的项写成 `不写时的值;empty=写成空值时的值`
# （例：ENABLE_POLL_RUN_LOG 不写 = 开、写成空值 = 关，登记成 `true;empty=false`）。
# 开关的「关」可以是空值（`bool:on:`）。
#
# 「不写这一行时的值」必须和 daemon 实际用的一致——有的在 _lib.sh 加载时定，有的在 agent-poll.sh
# 用到的地方才补（${X:-默认}）。两类都和真实的使用方对拍（tests/project-config.test.sh 第 7 节、
# tests/project-config-poll.test.sh），新加一行就要补上它的对拍；改默认值时两边一起改。
# 模板里没登记在这里的配置项，都登记在 tests/config-fields-hidden.txt 并写明不显示的原因（tests/config-fields-coverage.test.sh 查）。
# edit 项只在「配置的代码里只提到它一次，且那是最外层单独一行、顶格写的普通字面值」时可改；写成算式、引用变量、
# 多处赋值、写在 if / 循环 / case / 函数里（一行写完的也算）、别处还提到它的只显示。代码里一次都没提到才算「没写」。显示的值一律是 daemon 实际用的：没设置 = 这里登记的默认值，为空 = 写成空值时的值（没另写就是默认值）。
