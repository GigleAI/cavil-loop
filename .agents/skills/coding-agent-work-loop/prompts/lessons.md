# 项目复盘经验

以下经验仅适用于本项目，不覆盖用户指令或安全约束。

`## 硬规则` 段的每一条都已在 3 个以上不同 PR 里被记录：worker 自审和交叉 review 必须逐条核对，适用而没做到的，review 打回。`## 观察中` 段是还没攒够次数的经验，适用时参考。编号永久不变；格式与计次规则见 `scripts/retrospective_lessons.py`。

计次来源的限制：迁移到本格式时的 Seen（只有 PR 号、不带链接的那些）取自旧版经验里该条规则引用的 PR 与证据链接，没有逐个回到复盘原文核实「这个 PR 确实犯了这个错」；带链接的 Seen 是之后的复盘程序按本次 PR 的评论证据追加的。

## 硬规则

### L1
- 规则：测试全绿、复审「实测通过」、PR 合并、生产已实际执行这几件事分别声明，不互相代替；「实测过的 / 没跑过的」分栏披露。
- 适用：交人评论、复审结论、复盘里提到验证或上线状态。
- 为什么：多个 PR 合并时，真实 daemon 全链路、真实 codex 模型层、部署执行都未验证。
- Seen 8×: #26 · #33 · #48 · #50 · #54 · #55 · #57 · #59

### L2
- 规则：修改复审 / 派工工具自身运行时依赖的脚本或模板时，主动声明「合并前复审和派工仍用旧版」带来的验证滞后。
- 适用：改到 daemon、prompt 模板、driver 等会被本次 review 自己用到的文件。
- 为什么：技能目录软链接指向 main checkout，复审 footer 曾因此显示「未配单价」。
- Seen 9×: #27 · #31 · #37 · #39 · #44 · #48 · #50 · #55 · #57

### L3
- 规则：同类问题被复审发现第二次变体时，系统性收口而不是逐点打补丁：枚举全部读、写、入队环节，配跨轮测试及旧实现负对照，必要时把「是否收敛设计」明确交人。
- 适用：校验、状态机、并发、汇总与多处调用的逻辑。
- 为什么：fail-open 校验放在放行判断之后、「先记已处理、后做可能失败的读写」永久漏掉失败，这类问题都反复出现过。负对照须确认红来自语义退回，而不是语法错误。
- Seen 6×: #39 · #44 · #54 · #59 · #48 · #47

### L4
- 规则：判定人工是否已拍板，落到具体评论 URL、`created_at` / `updated_at` 和正文核对（勾选、文字答复、只改 label 都可能是拍板），不凭「最新评论是自己发的」或「label 已翻回」推定；查不到勾选编辑者就写「出自谁未验证」。
- 适用：复盘、审计、派工判断人工意图时。
- Seen 6×: #22 · #39 · #48 · #57 · #32 · #51

## 观察中

### L5

### L6

- Seen 0×:

### L7
- 规则：独立复审用对应阶段的标准：方案阶段审「值不值得看」，不得以「没实现 / 没测试」打回。
- Seen 1×: #34

### L8
- 规则：密钥环境变量跨进程边界时，一次性覆盖参数不复用持久配置的同名变量；配置里不带 export 的变量显式传给子进程（需全新变量名 + `env -u` 暴露），并做跨边界回归加负对照。
- Seen 2×: #30 · #55

### L9
- 规则：安装脚本显式 `chmod 600` 密钥文件，并对老安装补做。
- Seen 1×: #36

### L10
- 规则：daemon 新增的 GitHub 写调用走读写身份分离（`gh_write`）。
- Seen 1×: #26

### L11
- 规则：GitHub Project v2 字段写权限、仓库标签写权限、OAuth `project` scope 互相独立；权限不足如实上报交人，不擅自提权或静默跳过。
- Seen 1×: #31

### L12
- 规则：会话 / 资源的归属靠正向证据（自发 id、接管前快照、与本次启动绑定的唯一标记），举证不了就拒绝并留诊断，不靠「当前没登记给别人」「启动后才出现」「首行相同」这类排除法或出现顺序。
- 这样做是对的：真实形状夹具（多行模板、前置上下文消息、两个角色方向）加逐入口单点负对照。
- Seen 1×: #33

### L13
- 规则：根因排查、方案设计与问题复核，对「看似显然」的假设做独立实测。
- Seen 2×: #34 · #26

### L14
- 规则：依赖外部工具的解析结果时，委托工具自己解析（无副作用探测），不手工复刻它的优先级、拆词或落盘格式；必须自己解析时先读一份真实产物，用白名单，拿不准就不追加并记日志。
- 这样做是对的：PR #57 改为直接问 CLI，结束 5 轮返工。
- Seen 2×: #57 · #33

### L15
- 规则：同一判定被多处调用（含生产者与消费者各自判断「是否已有值」）时用同一个键 / 共享函数，逐处断言并分别做负对照，覆盖合法零值（`is not None` 而非真假判断）、别名 / 日期后缀名、不同写入顺序，并保留「来源」与「可信状态」两个独立维度；jq 与 Python 两份实现用同一输入逐字段比对。
- Seen 1×: #55

### L16
- 规则：开 PR 与合并前把新测试跑在最新 base 上；合并 base 后重新核对横切参数和 `$SELF_DIR` 一类路径写法是否落到新增代码路径，确认末尾共用结尾行没被合并丢失。
- Seen 2×: #33 · #55

### L17
- 规则：fail-open 校验须在所有放行判断之前统一执行；轮询状态机不得「先记已处理、后做可能失败的读写」；同源汇总复用同一份中间结果。
