本 PR 没有暴露新的流程失误：没有返工，没有被复审指出的缺陷。问题发生在上游：#322 的复审条件和提示词条件相同，都以"有选择题"为前提，所以漏检了没有选择题的界面改动。这个问题在 #335 里已经被识别，本 PR 是对它的修复。

## 最佳实践（有适用条件）
- **适用条件**：同一条规则要出现在多个入口（多份模板加复审）时。
  做法：把规则文字集中在共享的一段里，引用而不是复制，例如安全规矩只写"照评论配图标准"。
  验证：成品逐字比对，并经真实派工脚本渲染各入口。本 PR 用了这种做法，复审认可。
- **适用条件**：放宽触发条件时，把"生成侧要求"和"复审侧检查"在同一个 PR 里一起改，并给出没有前置资源时的退路（本例是未配出图地址就写明未配置并用文字描述）。这样规则放宽后不会把项目卡住。
- 交付计数写明命令，并区分自报与复审复跑的数字。
