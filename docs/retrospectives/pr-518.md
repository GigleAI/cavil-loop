## 经验教训
1. **返工原因**：「页面尚未标记主题」这个兜底状态，首版只补了根节点背景，漏掉 body 实际使用的颜色变量。首版测试没有覆盖「标记缺失」的时刻，复审用 Chromium 复现才发现。
2. **推断（非确认）**：深浅色令牌因 macOS 14 的网页引擎限制只能复制一份，这是该问题的结构性背景。返工评论说明了这一限制，复审通过时认可了对拍测试。

## 最佳实践（有适用条件）
- **适用**：一个状态在多处被读取的主题 / 配置，且存在「尚未初始化」的过渡状态。
  - 做法：把过渡态与稳定态的全部取值逐项对拍，并断言实际绘制结果（计算样式、实际底色），不只检查根节点。
  - 验证：把测试套到旧样式上应变红。
- 共用规则一处决定、各调用点读同一个值（`resolveTheme` 加 `useDarkMode`），界面测试在同一屏同时断言多处。这对应已有规则 L3，是做对的案例。
- 读不懂 / 读不到系统状态时，按「跟随系统 / 浅色」回落，不记录任何东西。这对应 L36，是做对的案例。
- PR 正文的测试数字附命令，复审复跑一致（2170 项）。这对应 L34，是做对的案例。
- 这些只是本次采用的做法，不是唯一正确架构。
