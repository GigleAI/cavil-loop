## 经验教训
- 已确认:「0 秒」同时代表「确认没跑」和「没计上」会产生歧义。拆出第三态 `unknown`,才能让读的人分清「没跑」和「没取到」。
- 已确认:三种不同原因(没配命令、没跑、取不到)原先输出相同,读者无法区分。信息缺失时应显式写出状态,不应静默省略。
- 推断:迁移表缺 L1 #79 的出处是 main 上既有缺陷。它是否由前序 PR 引入,没有证据。

## 最佳实践(有适用条件)
- 适用:状态有「没发生」与「没测到」两种含义时。做法:分开表示,并为每个状态写一条检查。验证方法:把实现改坏做负对照,确认对应检查变红。
