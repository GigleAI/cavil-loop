## 经验教训
1. **按整机特征切换布局是缺陷根源(已确认)。**
   - PR 正文自称 L3 已做到,理由是路径选择只有一条规则、有对拍。
   - 但对拍覆盖的是"路径选择"本身,没有覆盖"先有旧登记、后装新单元"的跨轮状态。
   - 新旧各自单测通过,共存才暴露问题。
2. **多个读取点按不同依据取源(已确认)。**
   - 管理端按机器上的模板选目录,启动端按登记存在性选文件,systemd 单元固定读旧目录。
   - 这属于 L3(同一配置多处读取)的又一次出现。
3. **推断(未验证):** 如果设计阶段列出"新旧共存"的状态矩阵,可能更早发现。

## 最佳实践(有适用条件)
- 适用于新旧布局并存的兼容改造。
  - 选择依据尽量绑定到资源自身的登记或单元,而不是整机"装了哪套"。
  - 只有全新创建才按整机状态选。
  - 验证方法:写"旧状态 → 装新组件 → 列表 / 注销 / 跨项目抢占 / 启动读源"的跨轮行为测试,并对上一版做负对照。
- 这是本次采用的一种做法,不是唯一正确架构。
- 对已部署的旧单元文件保持字节不变,新增另一套。
  - 事实:PR 正文称这样可避免每台机器告警。
  - 部署器的一次性告警仍会出现,PR 已事先披露。
- PR 正文单列"还没验证的"并说明合并部署前线上仍是旧代码。这符合 L11,是照做的案例。
