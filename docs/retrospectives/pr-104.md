## 3. 经验教训
1. **「跳过」只写在汇总和断言上不算跳过(已确认)**:开关判断放在 `expect_red` 里,调用者早已执行完沙盘复制和改模板。输出「跳过 N 项」,实际仍触碰了负对照专用的源码原文。
   - 两种模式的全绿输出都检测不出。只有读执行轨迹(`bash -x`)并按入口核对,才暴露出来。
   - 推断:13 个入口各自手写调用方式,是遗漏的结构性原因。更稳的做法是让开关函数直接包住准备步骤。
2. **到达性断言要用「演示提前退出」来证明有效(已确认)**:每个大测试都有「入口直接 return」的演示,并如实写出哪几条仍是绿的,这样能看出覆盖缺口。
3. **别把某个设计当成标准答案(推断)**:`neg_sandbox` 先判开关再建沙盘是本 PR 的一种实现,不是唯一做法。

## 4. 最佳实践(含适用条件与验证方法)
- **适用:给慢速或重复性检查加开关。**
  - 做法:开关判断放在第一个有副作用的准备步骤之前。
  - 验证:在关闭模式下数副作用次数(建沙盘、复制、改文件),或看执行轨迹。不要只断言汇总文字。
  - 验证:再把开关位置改回准备之后,确认断言会变红。
- **适用:从回归中移走负对照后补到达性断言。**
  - 做法:给每条只靠「没发生」成立的断言配一条「确实发生了」。
  - 验证:让被测入口提前返回,默认模式必须变红。
- 开关取值只认明确的 0 和 1,其他值报错,不要悄悄当成关闭。
- 开关关闭时让「准备失败」的自检直接报错,不要静默通过。
- 一个计数器同时产出「跳过 N」和「跑了 N」,两者不靠手写常数。
- 开关与实测数字分别披露:worker 自报和复审独立复跑要分开写。

## 5. 流程改进
- 复审时,给一类入口多、写法各异的开关或约定,要求逐入口核对,并保留执行轨迹或副作用计数作为证据。
- worker 自审表不要只写「共用计数函数存在」,要写每个入口的行为证据。
- 复审附加指令里的新约定(复审可跑 `MUTATION=1`)合并后才生效。本 PR 的复审仍用旧附加指令,这一滞后已在 PR 中如实披露。

## 6. 适用边界
- 本 PR 只涉及 shell 测试套件和文档。上面的原则不自动适用于有真实外部副作用的场景。
- 耗时改善是单次测量,不保证在其他负载下复现。
- 默认模式不再核对负对照所要找的源码原文,代价是源码重构后原文过期要等有人开开关才发现。该取舍已写进设计方案,并经复审确认。
