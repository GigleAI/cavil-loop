## 经验教训
1. 同一规则写进多份模板或多个审查点时，对拍成品「逐字一致」不等于每个写入点各自受保护。通用段里同文的副本会掩盖附加段的缺失，因为比较前先去重。这和 L3 说的是同一件事，本 PR 计入。
2. 对拍用的「旧版本」基准如果取随主干移动的引用，就会随合并漂移，导致无关 PR 红或恒红。这是新观察（L47）。

## 最佳实践（有适用条件）
- 适用：同一规则被复制到多个位置时。做法：先把所有写入点一次列全，每点一条正向断言加一个独立负对照。验证方法：对每个点单独改坏一份沙盘副本，跑默认回归，必须变红；并用同一份改坏输入对拍新旧测试。这是本次采用的一种做法，不是唯一的架构。
- 适用：回应复审的同根因问题时。不只补点名的点，而是盘点全部写入点。本次第 2 轮复审据此直接通过。
- 适用：交付说明里。把「未验证」单列，写清合并部署前线上仍是旧版、测试证明不了 agent 照做。

## 流程改进
- 复审时让对比基准固定（取固定提交，或「首次引入某文件的提交」的上一版），不要取随主干移动的引用。
- 守护进程因 worktree 占用而暂停的情形，本 PR 证据不足，不下结论。
