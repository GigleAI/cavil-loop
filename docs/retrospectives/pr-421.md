## 结果与证据
已确认事实：
- 推 `client/v0.5.2` 前，agent 在 main 上手动跑完整客户端 CI，界面测试 121 项全过，真实 App 测试「隐藏启动」一项两次都红（`element not interactable`）。来源：PR 正文、#378 评论。
- 根因（PR 正文称本机实测）：设置页变长，勾选框在 y=851，窗口高 820；设置页平滑滚动，驱动在动画未完成时检查元素。App 本身没问题。
- 修法：公共 `click` 里先同步、瞬间滚动同一元素，再走原 WebDriver 点击；没有用 DOM click 绕过交互检查。
- 验证：PR 正文称修前本机复现 1 failed、修后本机 8 passed；复审独立重跑 8 passed、typecheck 通过，并读到分支 CI（43167778853）界面 121 通过、真实 App 8 通过。这些数字出自评论，本复盘没有复跑。
- 复审没有行内评论和 review 返工，一轮通过后由 daemon 合并。

未验证 / 未完成：
- 合并不等于 `client/v0.5.2` 已发布。#378 后续（在 main 重跑完整测试、推标签、核对附件和签名、文档 PR）截至本 PR 合并时尚未完成，复审也明确未验证 macOS 打包与发版。

## 经验教训
1. 完整真实 App 测试平时不在 main 每次合并上跑，设置页变长造成的点击失败（由先前改动引入）拖到发版预检才暴露。（事实：#378 评论称 main 合了约 30 个客户端改动、期间 CI 只跑快速测试。）发版因此连续多出两个修测试 PR（#412、#421）。这里的因果是推断：缺少合并期完整覆盖是原因之一，但没有数据证明是唯一原因。
2. 测试驱动的点击能力不应依赖元素恰好在可视区内；人会先滚再点，驱动应模拟同样的前置步骤。

## 最佳实践（有适用条件）
- 适用：真实桌面 App + WebDriver 测试，页面存在平滑滚动或内容会增长时。做法：把「滚进视口」放进唯一公共点击函数，而不是在个别用例里补；不改 App 的平滑滚动去迁就驱动。验证：本机单跑原失败用例并跑全套真实 App 测试，必要时用诊断读元素位置与窗口高度。
- 适用：要打不可撤回的发版标签前。做法：先在目标提交上手动跑带完整测试的 CI，绿了才推。本次预检避免了又一次「标签推上去但不建发版页」。这是本次采用的一种做法，不是唯一方案。
- 修复范围与根因对齐：只改测试、不动版本号和 App，PR 正文列出排除的方案及理由。
