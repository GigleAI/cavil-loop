- PR 改了 6 个文件：复审模板第 3 步加规矩、新测试、中英运维文档、测试清单。daemon 代码未改（PR 正文）。

## 最佳实践（有适用条件）
1. 同一条规矩要在多种拼装成品（带 / 不带项目附加指令）里生效时，只保留一份原文，测试对每种成品分别断言，并各做一个「删掉规矩」的负对照。验证方法：负对照改坏沙盘副本后重新拼装，测试必须变红。（L3、L4，PR 正文自述，复审复跑确认）
2. 方案阶段把范围边界写清：做什么、不做什么，哪些评论不加标记。例如 worker 评论和安全警示评论不加。自己能定的不做成选择题。适用于小范围、不改对外可见权限的改动。
3. 分栏披露「实测 / 未验证」，并写明合并部署前仍是旧指令。（L11）
4. 只见 relabel 时写明「未见书面确认」。（L9）
