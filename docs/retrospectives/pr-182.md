1. **默认项不能悄悄扩大对外可见范围（方案阶段，已确认）**：方案把「重开」设为默认 A，被复审打回。修复是收回范围，重开另行提出。
2. **只改名也要保留原有的行为说明（已确认）**：提示文字里带有焦点限制，改名时容易丢。
3. **复审通过后主干推进会造成冲突（已确认）**：冲突只在发布说明一处。worker 同时核对了 #173、#177 的新约定是否影响关闭 issue，并重跑测试。

## 最佳实践（有适用条件）
- 适用：同一规则有多个出口（颜色有徽章、卡片、表格三处，关闭原因有界面和数据层两处）。做法是只保留一份判断或一份列表，再用同一条目在各出口对拍。验证方法是对每个调用点做负对照。
- 适用：写操作带有先后副作用（先关闭再评论）。做法是只在前一步成功后做后一步，评论失败只给警告，不重发关闭。验证方法是假 GitHub 记录请求顺序，并配「被拒时零评论」的用例。
- 适用：依赖外部状态决定是否出现入口。读不到状态时不显示入口，不把读不到当作「开着」。
- 适用：引用测试和负对照计数。写明命令、提交和范围，并如实披露偶发失败，不写成全量验证。本 PR 的做法被独立复跑印证。
- 零请求和拒绝类断言要配同一路径能成功的正向用例。
