## 4. 最佳实践（有适用条件）
- 同一段文字要出现在多个 prompt 入口时，适用于入口较多、容易漏改的情况。做法：让测试走真实的拼装函数，对拍成品是否逐字一致，并对每个写入点做负对照。验证方法：把测试放到旧版上应当失败，逐点删除应当被拦下。
- 改的是 prompt，无法稳定自动测试模型行为时，把人工演练标成「演练」，并写明它的区分力有限（本 PR 承认旧版也能挡）。验证方法：报告里能读到「证明了什么、证明不了什么」。
- 改到派工或复审自己运行时依赖的模板时，同时写明合并部署前仍用旧版。
- 不要把本次「不做自动扫描代码名字」的决定当作唯一做法；它的理由是误报多（见方案评论），换了场景可重新评估。
