## 最佳实践（有适用条件）
1. 改数据表时，先在方案里写清"做 / 不做"及理由。能力不足的条目（如分档计价型号）宁可显示"无单价"，也不要放一个会悄悄算错的单价。适用于表结构表达不了完整定价的场景。验证方法：不做项仍显示"没有可用单价"。
2. 期望值按官方价手算，不从被测表反推。再用旧表加新测试做负对照，确认测试能区分对错。适用于任何数据驱动的计价测试。
3. 一份数据有多个消费者或副本时，让消费者读同一个来源。副本（配置示例、文档）逐项对拍。本 PR 的做法是 Claude 参照表只有一份源码，codex 三处靠一致性测试对拍。
4. 交付正文单列"还没验证的"，把测试通过、合并、部署分开说。
