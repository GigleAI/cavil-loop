## 3. 经验教训
1. 开工后到达的需求转达可能让当前复审意见作废;开发方在改动前没有重读最新的人工口径,多修了一轮(见上)。
2. 数据量级差几十倍的指标,双轴或同轴堆叠都会引起误读;可视化口径需用真实量级数据让人看过,才能确认。本 PR 的两次人工纠偏都发生在看到真实数据图之后。
3. 测试固化了旧方案的断言,需求变更时需要同步重写,否则"全绿"掩盖不符。
4. 单位/文案不要写死,须与实际数据格式一致,并用跨阈值样本检查。

## 4. 最佳实践(附适用条件与验证方法)
- **适用于存在多个人工/复审/转达渠道的任务**:每次改动前,按时间重读各渠道中晚于上次提交的人工要求;验证方法:交付评论列出所采用的最新人工口径及其链接。
- **适用于数值展示类改动**:先用接近真实量级的数据渲染看图,再定图型;验证方法:样本包含量级差 ≥ 10 倍的项,检查各项在图中可辨。
- **适用于视觉/格式断言**:用互不相等的样本、阈值两侧样本,并对旧实现和错误变体做负对照。这是本次采用的手段,不是唯一做法。
- 拆图或改变产出物数量时,同步检查流水线、文档和引用点;无法实跑的部分单列"未验"。
