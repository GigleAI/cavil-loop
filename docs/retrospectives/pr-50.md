## 3. 经验教训
1. **新增汇总指标容易绕过已有的去重规则。** 金额已经按调用认领去重，新增 token 汇总却直接读原记录，导致重复计入。教训：同一事实的不同度量（金额、token）应共用一个取数入口。证据：复审 P1，见 #50 第 1 轮复审。
2. **估算值和重算值的优先级必须明确。** 可重算的记录应采用重算结果，估算只用于回退记录。重叠且无法可靠去重的用量要单列并说明，不能混入主指标。修复评论和第 2 轮复审都确认了这一点。
3. **图表的范围计算要匹配图形语义。** 堆叠柱的高度是各项之和，只验证面板数量、页高、标题发现不了越界。需要在坐标或轴范围层面断言。见 P2。
4. **初版测试样本太窄。** 只有不重叠、无本机日志的样本，区分不了错误实现。这是复审对初版测试的判断。
5. **推断：** 复审提出的两个缺陷都落在"新增字段没接入既有规则"和"新增图形复用旧的范围计算"。本次只有一个 PR，不能确认这是项目内的普遍模式。

## 4. 最佳实践
- **适用条件：** 新增一个与已有指标同源的汇总字段，而已有指标有去重、认领、回退等规则。
  - 做法：复用同一份中间结果，而不是重新从原始记录读取。
  - 验证：构造重叠、可重算、需回退三类样本，对旧实现做负对照。
- **适用条件：** 用经验比例或参考价对历史数据补估算。
  - 做法：
    - 估算与重算分来源标注。
    - 无原值的记录不补出金额。
    - 报告写明估算方法和偏差范围，估算周在表中用 `≈` 标记。
  - 验证：检查这三类记录的来源和显示，并用负对照确认估算不会覆盖重算值。本次的一种做法是 ÷1.68，不是唯一正确口径。
- **适用条件：** 新增图表面板，且数值是堆叠或叠加后才显示。
  - 做法：用真实渲染函数产出 SVG，断言所有图形元素落在绘图区内，再断言轴上界不小于最大堆叠和。
