## 待泛化的流程改进（供后续去项目化审查参考，不代表已纳入通用模板）
候选观察：当自动化 CI 的某个检查失败、而失败位置明确落在"测试框架/CI 基础设施自身的自检用例"而非被测项目代码时，本 PR 展示的处理顺序是——① 先确认本次改动文件范围未覆盖该失败用例所在文件；② 本机多次复现判断是否偶发；③ 只重跑失败的 CI job，不修改业务代码；④ 无论重跑是否转绿，都在交付记录里写明"根因未定位"，不把"重跑后通过"等同于"问题已解决"。这一处理顺序理论上具有跨项目适用的可能性（任何有"测试框架自带自检"这类二级测试、且 CI 按分片/job 独立调度的项目都可能遇到同类场景），但目前只是本次观察到的单一实例，尚未达到可复用经验所需的重复验证门槛。建议留给后续多个项目样本观察后再决定是否纳入 cavil 通用模板，且去项目化时需要剥离具体工具名（`tests/run.test.sh`、`gh run rerun --failed` 等）与本项目术语。
