## Cavil Loop 客户端

本地看板客户端：把多个 GitHub Project 和仓库放进一个视图，按迭代 / 状态 / 里程碑分列，可按仓库分泳道；也可以切成表格，按迭代 / 状态 / 里程碑 / 仓库分组。顶部搜索框用 GitHub 网页的筛选写法（`label:` `-status:Done` `iteration:@current` `assignee:@me`……），在本机对缓存数据筛，中文词中间也能搜到。添加 Project 时自动导入它网页上存的视图（布局、分组、排序、列、筛选）。点卡片看详情（评论最新在上），可以加 / 删标签、改迭代 / 状态 / 里程碑（下拉或拖卡）、新建 issue、回复评论并一键交回 agent、直接勾评论里的选择题、合并或关闭 PR、关闭 issue；断网时显示上次同步的内容，这些修改入口都变灰。开着的 issue / PR 新挂上 `pending/human` 时发系统通知（点开回到 App 并打开那一条），Dock 角标只显示还没看过的新条目数（切到 App 就清零，通知留着、点哪条收哪条）；关掉窗口后在后台继续同步。

### 这一版（0.5）

- **标签选择框里 `pending/later` 排到 `pending/human` 正后面**（GitHub#513）：暂缓标签和等人处理一样常用，以前混在其余标签里、通常排在最后。现在详情、表格标签列、新建 issue 三处的置顶顺序是 `autopilot`、`pending/human`、`pending/later`、`pending/agent`。设置 →「流程标签」多了一格「暂缓的标签」，默认 `pending/later`，要和 daemon 配置里的暂缓标签一致；改了名就按新名字置顶，留空就不置顶。
- **设置里可以选浅色 / 深色**（GitHub#516）：设置 →「外观」（排在「语言」下面）三选一：「跟随系统」（默认，和以前一样跟着系统变）、「浅色」、「深色」。选了立刻生效，整个窗口一起换——看板、表格、依赖图、详情和讨论区、标签颜色、代码高亮，macOS 上窗口标题栏和菜单也跟着变；系统中途切换深浅时，只有「跟随系统」跟着变。选择只存在这台电脑上，重开 App 还在。
- **顶栏的数换了默认顺序、多一个「稍后处理」；设置里能实时预览；设置页各块说明精简**（GitHub#514）：没改过「顶栏计数」的，顶栏右侧从左到右变成「未处理 / 等人处理 / 等 agent / 运行中 / 稍后处理」。「稍后处理」数开着、挂 `pending/later`（daemon 的暂缓标签）的条目，标签名在设置 →「流程标签」新加的「暂缓」一格里改，留空就不显示这个数。自己改过顶栏计数的人，顶栏保持原样，点「恢复默认」才换成新顺序。设置 →「顶栏计数」表格上方多了一条预览，和顶栏一模一样、按当前数据计数，改名称、颜色、顺序、条件时当场就变，不用回看板看。设置页每一块开头只留一句话，原来的长说明原样收进各块底部可点开的说明里；目录里「交给 agent」改叫「流程标签」，「登录方式」并进「账号」一块。各设置项、按钮、提示条和它们的作用都不变。
- **发评论、改正文 / 评论、改标题、勾任务点下去就不用等了，结果在窗口顶部的通知区**（GitHub#489）：回复框立刻清空，编辑框立刻关上，发出后马上关掉浮窗、切到别的标签页、换一条都不影响它发完。发评论、改正文 / 评论成功时顶部绿色一条、5 秒自己收起；勾任务、改标题本来就看得到结果，成功时不另报。GitHub 明确拒绝（或根本没发出去）时，文字放回那一条的编辑框：回复框里有字就接在后面，改正文 / 评论 / 标题的编辑框重新打开、原文填回；那一条没开着时，通知写明「打开这一条时会放回」，也可以点「再发一次」。没收到 GitHub 回答时（断线、超时），文字只留在通知里、不放回编辑框——它可能已经发出去了，再发会重复；通知上只有「再查一次」（只读，不会再发）和「已核对，解除锁定」，客户端自己也会每轮同步再查，查到那条评论（或 GitHub 上已是改后的内容）就变成已完成。重启客户端后这些记录都还在。这期间同一条正文 / 评论 / 标题不能再改，发别的评论不受影响。
- **讨论里每一条的折叠行显示这一轮的总耗时，不再放「在网页上看」**（GitHub#503）：loop 发的评论，折叠行在时间后面显示这一轮 agent 用了多久（例如 `⏱️ 42m 7s`），和评论末尾用量那一行写的「耗时：」完全一样；一行摘要里不再重复用量那一行。人写的评论、没有用量记录的评论不显示。要打开某一条的网页，展开它，点底部右侧的「在网页上看这一条」；整个 issue / PR 的网页按钮不变。评审（review）不显示耗时。
- **标签选择框打开时，已挂的标签排最上面，常用的流程标签紧跟其后**（GitHub#496）：详情里的「+ 加标签」（`L`）、表格的标签列、新建 issue 窗口三处都一样。以前按仓库标签的原顺序列，已挂的标签可能在最下面要往下滚才看得到。现在打开时已挂的标签打着勾排在最前，接着是常用的流程标签——这一版起是 `autopilot`、`pending/human`、`pending/later`、`pending/agent` 四个（`pending/later` 由上面 GitHub#513 那条加入；跟着设置 →「流程标签」里的名字走，仓库没有的不列），其余照原顺序。开着时点一下只变勾，行不挪位置，关掉再打开才按新状态重排；输入筛选后也是这个顺序。里程碑选择框（`M`）把当前里程碑排在第一。
- **浮窗头部的「在标签页打开」改成普通按钮**（GitHub#505）：原来是蓝底白字，深色模式下蓝底太亮，白字看不清（对比度只有 3.10）。现在和旁边的 GitHub 网页按钮、刷新按钮同一种样子：灰底、正文色文字、细边框，鼠标移上去也照普通按钮变化；图标、文字、位置和浮窗太窄时只留图标都不变。
- **⌘F 在页面上查找文字**（GitHub#502）：按 ⌘F（Windows / Linux 上 Ctrl+F）右上角弹出查找栏，像浏览器的「在页面中查找」：找到的字全部淡黄色高亮，当前那一处橙色并滚到眼前，栏里写「第几处 / 共几处」，没找到时变红。↩ / ⇧↩、⌘G / ⌘⇧G 或栏上的箭头跳到下一处 / 上一处（到头绕回），Esc 或 × 关掉、高亮一起去掉。详情的讨论区也算进去，匹配在收起的评论里时跳过去就展开那条；讨论区里按 ⌘F / ⌘G 也有效。查找栏开着时，不管光标在哪（查找栏、页面、讨论区），Esc 都先关查找，再按一次才是原来的作用（收起浮窗、回首页等）。看板顶部的搜索框不受影响，仍由 `/` 跳过去；输入框、回复框里打的字和回复的预览不在查找范围内。同步改了页面时个数自动更新。整页同时高亮要 macOS 14.2 及以上的系统网页内核，更早的系统只把当前那一处选中显示；macOS 上还没在真机上按过（自动测试在 Linux 窗口里按的是 Ctrl）。
- **Mac 上切看板 / 表格 / 依赖图改成 ⌃⌘1 / ⌃⌘2 / ⌃⌘3**（GitHub#492）：同时按住 Control 和 Command 再按数字。按钮提示和快捷键一览在 Mac 上只写这三个；以前的 ⌥⌘1/2/3、⌘⇧1/2/3 照样能用，只是不再写出来。Mac 上 ⌃⌘ 一起按住算单独一组键：以前按 ⌃⌘1 会被当成 ⌘1 切到第 1 个标签页，在讨论区里按也一样，现在都不会了；⌘1 … ⌘9、⌘R 照旧。Windows / Linux 不变，仍是 Ctrl+Shift+1/2/3。macOS 上还没在真机上按过（自动测试在 Linux 窗口里模拟 Mac 的按键）。
- **搜索框默认留空，视图栏加「显示已关闭」开关，每个视图各记一份**（GitHub#464）：新装的客户端搜索框不再预先写 `-Status:done -label:Done`。视图栏「视图设置」左边多一个「显示已关闭」开关，默认关，只显示开着的 issue / PR；打开后连已关闭、已合并的一起显示。开关按视图分别记：看板、表格、依赖图各一份，顶栏每个数点亮时也各一份（包括设置里自己加的数）——「等人处理」连已关闭的也数，它的开关一开始就是开的，点开就能看到已关闭但还挂着 `pending/human` 的条目，想只看开着的就单独关掉它；其他数一开始只列开着的；切回看板后看板的开关保持原样；重开 App 都还在。点亮某个数时搜索框写的是 `label:"pending/human"` 这样的句子，不再带 `is:open`。搜索框里自己写了 `is:open` / `is:closed` / `is:merged` 时以搜索框为准，开关变灰。依赖图关着开关时，开着的条目要用到的已关闭父项、前置、子项仍淡显画出。导入 Project 网页视图时，只用来挡已完成条目的写法（`-status:done`、`-label:done`、`is:open`）不再放进搜索框，其余照导入；升级时搜索框整句只由这几个写法组成的会被清空，原来点亮的数照样亮着，夹着其他写法的不动。注意：原来按 Project 的 Done 列 / `Done` 标签挡，现在按开 / 关状态挡，开着却已拖进 Done 列的条目会重新出现，想继续挡就在搜索框写 `-status:done`。开关只管已读到的条目：仓库来源仍只读全部开着的、近 14 天更新过的和挂着 `pending/human` 的已关闭条目。
- **单击条目回到右侧浮窗，标签页要的时候才开；没开标签页时不显示标签栏；「正在运行」不再转圈；⌘1…⌘9 切标签页**（GitHub#442）：点看板卡片、表格行、依赖图的框，和标签页上线前一样在看板右侧的浮窗里打开（左边缘可拖宽，点外面、按 Esc 或「收起 ›」收起，回复框里有字时点外面和 Esc 都不收起）；系统通知、刚建好的 issue、提示条里的「打开 / 重试 / 去回复」也一样。按住 ⌘ 点（Windows / Linux 上是 Ctrl）开成标签页并切过去，鼠标中键开成后台标签页；右键卡片 / 表格行 / 依赖图的框弹出菜单：在浮窗打开、在新标签页打开、在后台标签页打开、在 GitHub 网页上看。已经开着标签页的条目单击直接切到那个标签页。浮窗属于首页：切到别的标签页再回来，浮窗还在，没发出的字也在；浮窗正开着的那一条被开成标签页时，字跟着进标签页。一个标签页都没开时整条标签栏不显示，关掉最后一个就消失。标签上「agent 正在处理」的图标换成静止的蓝底小机器人（和「等待人处理」的黄底人像成对），原来的转圈看着像页面还在加载。⌘1 … ⌘9 改成切到第几个标签页（⌘1 是首页，⌘9 是最后一个）；看板 / 表格 / 依赖图挪到 ⌘⇧1 / ⌘⇧2 / ⌘⇧3，Mac 上另有 ⌥⌘1 / ⌥⌘2 / ⌥⌘3——Mac 默认把 ⌘⇧3 留给整屏截图，窗口收不到。首页而浮窗开着时 ⌘W 收起浮窗。详情标签页在前时 ⌘R 重新读这一条（同详情的刷新按钮，讨论区、回复框里按也一样）；首页上 ⌘R 照旧是立即同步。macOS 上还没在真机上按过（自动测试在 Linux 窗口里按的是 Ctrl）。
- **在等前置的条目，标签页图标是灰底的暂停 ⏸**（GitHub#443）：挂着 `pending/blocked`（在等别的 issue / PR 完成）的条目，以前标签页上显示的是普通的打开图标，看不出它在等；现在换成灰底白色暂停图标，鼠标停上去写「等前置完成」，前置完成、标签摘掉后跟着同步变回原来的图标。认的是设置 →「流程标签」里「等前置的标签」那一格（留空就不显示暂停）；同时挂着「等人处理」时仍显示「等待人处理」。只看标签，不看 GitHub 侧栏的「Blocked by」。
- **详情改成标签页**（GitHub#397；打开方式、标签栏、图标和数字键已由 GitHub#442 调整，见上一条）：窗口最上面多了一行标签栏。最左边固定的「首页」就是原来的看板 / 表格 / 依赖图；点开的每条 issue / PR 各占一个标签页，详情占满窗口，不再是盖在看板右侧的一块面板。按住 ⌘ 点（或用鼠标中键）在后台打开；点标签上的 ×、按 ⌘W 关闭，⌘⇧] / ⌘⇧[ 切换，Esc 回首页。标签上的图标直接显示这一条的状态——agent 正在处理（转圈）、等待人处理、已关闭、已合并——并跟着同步自己更新；不在眼前的标签页有新动静时亮一个蓝点。没发出的回复跟着标签页，切走再回来还在，关掉有字的标签页前会先问。开着的标签页重开 App 后还在。「正在运行」认的就是设置 →「流程标签」里的「运行中的标签」（默认 `doing/agent`）。
- **详情里多一个「等前置…」：搜编号或标题选这一条要等的 issue / PR，登记后挂上 `pending/blocked`**（GitHub#434）：在「交给 agent」左边，也能按 ⌘⇧B（Windows / Linux 上 Ctrl+Shift+B）。对话框里先列出 daemon 现在认的前置；输入编号直接定位，输入文字按标题搜本仓库开着的 issue / PR，选好后列出确认后会做的几件事。issue 等 issue 写成 GitHub 侧栏的「Blocked by」，等 PR 时发一条 daemon 认的登记评论；条目从「等人处理」换成 `pending/blocked`，前置全部完成后 daemon 自动翻回 `pending/agent`。条目还挂着复审、运行中、交给 agent 这类流程标签时按钮变灰并写明原因。每一步写之前都重读一遍，期间有人改了就停下、提示停在哪一步；两份登记交错时，条目会保持暂停（挂着「等人处理」）并列出被盖掉的前置，再点一次「等前置…」就能补回。等前置的标签和依赖图读 loop 登记用的是设置页同一格（GitHub#429 加的那格，留空就两样都不做）；设置页「流程标签」一节另多一格「其他流程标签」（默认 `pending/*, doing/*, Done`）。macOS 上还没在真机上按过（自动测试在 Linux 窗口里按的是 Ctrl+Shift+B）。
- **依赖图也画 loop 登记的前置**（GitHub#429）：loop 让一条 issue 等别的条目时，前置常常只写在评论里的隐藏登记（`<!-- agent-blocked-by: #55 … -->`）里，GitHub 侧栏的 *Blocked by* 是空的，以前依赖图就一条线都没有。现在开着的 issue 挂着「等前置的标签」（默认 `pending/blocked`）时，客户端同步时读它的评论，找出 daemon 认的那条登记，把登记里的前置和 *Blocked by* 一起画成箭头（同一对只画一条），徽标「被 N 项挡住」「挡住后面 N 项」照算。哪条登记算数和 daemon 是同一套规则：最新的一条、在最近一次摘掉这个标签之后发的、daemon 自己「前置已完成」评论里的示例不算；只有一处不同——客户端不知道 loop 用的是哪个账号，只认仓库所有者 / 成员 / 协作者写的登记（loop 账号一般就是成员或协作者）。前置是 PR 时 PR 也画进图；不在已添加来源里的画成虚线；当前账号看不到的不画。设置 →「流程标签」多一格「等前置的标签」，要和 daemon 配置一致；留空就不读登记，图回到只画 *Blocked by*。改了这一格后马上重读，读到之前这些条目算「关系未知」。线只在客户端里看得到，GitHub 网页上不会因此出现 *Blocked by*；没挂这个标签的条目不多发任何请求。
- **评论里正常显示出来的图片，不再跟着一句「有 N 张图片不在 GitHub 的地址上」**（GitHub#439）：放在外站地址上的图片（例如 agent 发的截图）GitHub 会经它自己的图片代理显示，客户端本来就能加载，但数「有几张加载不了」时把 GitHub 顺带记下的原始地址也当成了图片地址，于是这类评论下面总有这句误报。现在只看图片实际加载的地址；真的加载不了的外站图片照旧提示，允许加载的图片来源不变。
- **「关闭 issue」「交给 agent」「托管」改用 ⌘⇧X / ⌘⇧Z / ⌘⇧C，回复框里、讨论区里也能按；按钮自带键帽**（GitHub#433）：原来的 X / ⇧A / ⇧P 在回复框里只是打字，点过讨论区之后又传不出来，所以写完回复想交出去时按不出来。现在三个键改成 ⌘⇧X 关闭 issue（仍只打开选原因的确认框）、⌘⇧Z 交给 agent、⌘⇧C 托管（Windows / Linux 上是 Ctrl+Shift+同一个字母），光标在回复框里、点过讨论区之后、在面板空白处都能按，和点按钮完全一样；在回复框里按「交给 agent」只改标签，框里的字不会发出去，留在框里。搜索框等其他输入框里按这三个键仍然不起作用。回复框里的 ⌘⇧Z 原本是「重做」，现在归「交给 agent」。回复框下面一行的键帽统一放进各自的按钮：「预览」补上 ⌘⇧P，「发送」按钮里放 ⌘↩，原来左边远处的「按 ⌘↩ 发送」去掉了。macOS 上还没在真机上按过（自动测试在 Linux 窗口里按的是 Ctrl+Shift）。
- **开发版的「更新了什么」不再漏掉没打成包的那几次改动**（GitHub#427）：一次合并的开发版没打成包（打包失败、被紧接着的下一次合并取消）、又没写更新说明时，它的改动以前在更新清单里完全看不到；现在下一个成功发布的开发版会在自己的更新内容里补上这些改动的提交标题（只算改了 App 本身的，只改测试、CI、文档的不列）。已经装着的 App 不用升级就能看到。

- **右上角的时间说清楚了；网络差时刷新按钮不再一直转**（GitHub#324）：右上角原来的「上次同步」只表示连上过 GitHub，数据没读成也会变新，和离线黄条的「数据截至」对不上。现在右上角写「上次检查 X」，离线黄条写「数据整份读取：X；上次检查：Y」——「整份读取」是眼前数据读下来的时间，「上次检查」是最近一次整份读取或问过 GitHub 没发现变化的时间；鼠标停在右上角能看到每个来源各自的两个时间、最后连上 GitHub 的时间和同步进度。检查看不到被删除、被转走的条目和看板标题、保存的视图的变化，这些要等整份重读。另外，网络差、一轮同步超过 1 分钟时，下一轮定时同步不再紧接着开始，而是等上一轮结束满 1 分钟，刷新按钮会停下来；改完之后的补读和点刷新不受影响。
- **在客户端里装 daemon、接上仓库**（GitHub#314 / #315）：设置页新增「本机 daemon」一节——检查这台电脑装没装 cavil-loop daemon、缺哪些工具（给出可复制的安装命令，客户端不替人装）、`gh` 登没登录；没装就点「安装」；列出已接上的项目，在跑 / 已停 / 读不到、上次轮询时间，确认后可以停、启、断开，打开日志和配置；代码目录形态的 daemon 可以「更新」。「数据来源」里每个仓库多一个「接上 daemon」：自动找本机已有的同仓库目录（按 origin 比对），没有就选位置克隆一份（可以用系统的文件夹选择框，也可以手填路径）；选 agent（默认 claude）后先检查这个 agent 需要的程序，缺的列出安装命令、「开始」不可点；点「开始」代跑 daemon 自带的安装脚本，输出边跑边显示，结束后读回 daemon 的状态确认真的接上了才显示「已接上」，失败时显示脚本的原话。客户端自己的 GitHub 登录不交给 daemon，daemon 继续用 `gh` 自己的登录。真实 Mac 上后台任务的登记、换新与回退只在 Linux 上用假的后台任务管理器测过，还没在真 Mac 上跑过。
- **旧版 daemon 也能在客户端里更新**（GitHub#320）：还没有状态脚本的旧 daemon（例如装在 `~/.agents/skills/coding-agent-work-loop` 的那批）以前只显示「读不到状态，请在终端里 `git pull`」。现在客户端自己判断它是哪种安装：是 git 代码目录就在提示下面给「更新 daemon」，做和平时一样的快进拉取（有没提交的改动、自己的提交分叉、origin 不在 github.com 时停下并原样显示 git 的输出），拉完自动重新检查、换新每个 Mac 项目的后台任务配置；拉完仍没有状态脚本（跟踪的远端分支上还没有它）时如实说明已拉取和当前分支。受管安装只说明它按设计会自动更新、为什么停在旧版本客户端判断不了；普通目录说明客户端更新不了、它也不会自己更新；判断不出时显示原因，都不给按钮。
- **详情里能改标题**（GitHub#299）：issue 和 PR 详情的标题右边多了一个铅笔按钮，点开改一行字、点「保存到 GitHub」（或按 ⌘↩；单按回车不保存），详情、看板卡片和表格马上换成新标题。只在这个账号能改这一条时出现，离线时变灰。保存前会再看一眼 GitHub 上的标题：在这期间别人改过就不保存、提示一句，输入框里的字留着，详情换成别人改的标题，从它再改即可。
- **新建的 issue 默认进当前迭代**（GitHub#276）：新建 issue 时，勾了的看板如果有迭代、而且今天正处在某个迭代里，加入时就把迭代设成它，不用再打开详情手选。顶部「新建」按钮、表格里按状态 / 里程碑 / 仓库分的组、「无状态」「无里程碑」组、不分组时的「＋」都这样；按迭代分的组照旧用那一组的迭代，「无迭代」组照旧不设。看板没有迭代、今天不在任何迭代里时只加入、什么都不说；同一块看板同时有两个当前迭代（日期重叠）时不猜，对话框里说一句。没勾的看板不受影响。
- **托管的 PR 也挂到 issue 下面；表格分组不再抢眼**（GitHub#275）：PR 正文里写 `Refs #N`（托管 PR 只这样写）、`Closes #N` 等点名的 issue，PR 都挂到它下面，「关联 PR」那一列也列出来（鼠标停在编号上看是 GitHub 关联还是正文引用）；PR 和 issue 的迭代 / 状态不一样时，PR 跟着 issue 显示在 issue 那一列 / 组里。表格里仓库标题最醒目、滚动时一直钉在顶上，分组标题变轻（不再着色、没有左边色条），组里的行缩进并带一条竖线；挨着的几个收起的组合成一行「已收起 N 组」，点组名只展开那一组。合并 PR 后「关掉了哪些 issue」不受正文里 `Refs` 的影响。
- **提交在仓库里的图片也能显示**（GitHub#267）：评论里引用仓库文件的图片（地址在 `raw.githubusercontent.com`，例如 agent 提交进仓库的设计图；写成 `github.com/…/raw/…` 的图片链接也会被 GitHub 跳到这里）在详情里直接显示，点图在浏览器打开原图。只放开这一个 GitHub 地址；私有仓库的这类图要登录凭据，客户端不带，仍显示不出来。
- **没变化时不再每分钟整份重读**（GitHub#261）：每轮同步先问 GitHub「变了没有」，这种问法在没变时不占 GitHub 的调用额度；没变就沿用上一份，变了才像以前一样整份重读。开着上千条的看板时，每小时用掉的 GraphQL 额度从约九成降下来（看板越安静省得越多，正在频繁改动的看板基本省不下）。条目、状态列、迭代的改动仍然最多约一分钟出现；保存的视图、看板标题、权限的变化最长约 10 分钟才出现——想马上看到就点刷新（或 ⌘R），手动刷新总是整份重读。
- **详情页不再挤压正文**（GitHub#260）：详情面板从「看板 / 表格」那一行下方开始，看板上方再多提示条也不会把它往下推，提示条只占左边看板那一块；面板里不再有整行提示——成功的结果（包括完全成功的关闭 / 合并 / 托管）是标题栏里一行绿色小字（10 秒后消失），失败、关闭 / 合并 / 托管的进度和结果、没保存上的修改收进标题栏带数字的按钮，点开再看、按钮照旧；标题栏新加一个按钮，可以把标签 / 里程碑 / 看板字段整块收起（记住，换条目、重开 App 都不变，收起时按 L / M 会自动展开）；PR 的合并信息挪到底部回复框里，和「合并…」「关闭 PR…」同一行，合并 / 冲突 / 检查 / 评审各一个图标（绿 = 没问题，红 = 有问题，黄 = 要注意，灰 = 还在算或没有），鼠标停在上面看原来那句话，分支和提交号也在提示里；有冲突时仍有一行红字、合并按钮不可点。
- **成功的提示 10 秒后自己消失**（GitHub#256）：「issue #N 已关闭（已完成）」「PR #N 已合并」「已托管」这类完全成功的提示，显示 10 秒后自己收起，不用再一条条点 ×；鼠标停在上面时不收，移开后再等 10 秒。没完成、不确定、部分失败、关联条目没读到、留着没发出的评论、人工解除过锁定的提示照旧一直留着，等人处理。改标签、改状态之后的绿色「已改好」结果条也一样 10 秒后收起。
- **角标只是未读数，不再统计历史**（GitHub#251）：App 启动或新加来源时，已经带 `pending/human` 的条目不再弹「N 条待处理 · 其中 M 条已关闭」的汇总，也不算进角标；之后只有开着的 issue / PR 新挂上标签才通知、角标加一。已关闭的 issue、已关闭或已合并的 PR 挂着标签也不再提醒。设置页「提醒」一节不再列出全部待处理条目和总数。
- **几处小改进**（GitHub#231）：「托管」确认框分成三段，底部可勾「不再提示」（默认不勾；设置里能改回来）；表格里收起的分组记住了，切到看板再切回来、重开 App 都还收着；「无迭代 / 无状态 / 无里程碑」组排到表格最后，和网页一致；迭代下拉按「当前 → 即将开始 → 已结束」排好，当前那一个标「（当前）」；新建 issue 时默认只勾这个仓库条目最多的那个看板（不管顶栏勾着什么），「会带上」的说明挪到看板勾选框下面。
- **开着的详情自己会更新**：详情页开着不动，别人（或 agent）发了评论、改了标签 / 标题 / 状态，下一轮同步（最多约一分钟）就显示出来，不用再点刷新；PR 的检查还在跑时每轮重新看一次，直到出结果。正在写的回复、展开的条目和滚动位置都不变。检查跑完后又被重新触发、而这一条本身没有别的变化时不会自动发现，点详情右上角的刷新。
- **表格选「全部」仓库时先按仓库分**：左边仓库栏选「全部」时，表格先按仓库分大组，每个仓库下面再按迭代（或状态、里程碑）分小组；仓库和小组都能各自收起。仓库标题旁的数字是这个仓库的条目数，同一条目落进两个小组只算一次。想回到不分仓库的样子，在视图设置里关掉「左侧按仓库切片」。
- **自动更新**：App 自己检查、下载并换上新版本，看板顶部提示「新版已下载」，点「立即重启」就是新版——**不用再下 dmg，也不用再跑放行命令**。详见下面「自动更新」一节。
- 已经装着 0.4 的话，0.4 里还没有自动更新，所以这一次要像以前一样手动装 0.5（含一次放行）；从 0.5 起就不用了。
- **在详情里直接勾选择题**：issue / PR 正文和评论里的勾选框（`- [ ] A. …`）点一下就勾上或取消，和在网页上勾一样改到 GitHub；勾完可以直接点「交回 agent」。没有修改权限的评论、评审意见里的框只读，那一条下面写着原因。
- **同步中也能点刷新（GitHub#217）**：后台正在同步时，右上角的刷新按钮不再变灰，点一下（或按 ⌘R）就放弃正在进行的这一轮、马上重新同步；图标转圈表示正在同步。详情里的「刷新这一条」读取中也能再点。

### 上一版（0.4）

- **界面换了一套（GitHub#181）**：看板、详情、表格、设置、登录五个页面统一配色和间距，浅色 / 深色跟随系统。顶上分两层：上层是数据来源、搜索、同步时间、新建 issue、设置；下层是看板 / 表格切换、分列、泳道、视图设置和条目数。卡片的状态用图标（issue / PR / 已合并各一个形状）加文字；详情的字段放进分格的表，PR 的合并区像 GitHub 的合并框；设置页左边是目录、右边一块一卡，每个来源写着有几条。深色下标签改成半透明底。功能和数据没有增减。
- **`pending/human` 提醒**：条目新挂上 `pending/human` 时弹一条系统通知，Dock 角标显示还没看过的条数，关掉窗口后照样同步和提醒。详见下面「提醒」一节。

- **常用快捷键**：回复框里 ⌘↩ 发送；详情里按 `L` 打开标签选择框（打字筛选、回车加上 / 去掉）、`M` 改里程碑、`R` 跳到回复框；任何页面按 `/` 搜索、`C` 新建 issue、⌘R 同步、⌘, 设置、`?` 看全部快捷键；对话框里 ⌘↩ 确认、Esc 取消。按 Esc 不会丢掉回复框里没发出的文字。
- **系统要求改为 macOS 14 或更新**：关掉窗口后还能继续提醒，靠的是 macOS 14 起才有的系统能力；macOS 11–13 上装不了这一版，请继续用 0.3。

### 更早（0.3）

- **安装包小了**：外壳从 Electron 换成 Tauri（用 macOS 自带的网页引擎，不再随包带一个浏览器）。上一版的 dmg 是 134 MB（Apple 芯片）/ 139.5 MB（Intel），这一版每个都在 20 MB 以内（发版流程里卡着，超过就发不出来）。
- **升级不用重新登录**：钥匙串条目、本地数据的位置都和上一版相同，装上新版直接接着用。
- **登录凭据只在后台**：GitHub 令牌只存在于 App 的 Rust 后台，界面部分从头到尾拿不到它；界面要读写 GitHub 都交给后台代发，后台只发往 GitHub。
- 系统要求：macOS 11 或更新。

### 下载哪个

- Apple 芯片（M1 及以后）：`Cavil-Loop-<版本>-arm64.dmg`
- Intel 芯片：`Cavil-Loop-<版本>-x64.dmg`

不确定的话：左上角苹果菜单 →「关于本机」，「芯片」一栏写 Apple M… 就选 arm64。

### 第一次打开（App 没有苹果签名，macOS 会拦一次）

打开 dmg 后的窗口里也写着下面的放行办法；双击窗口里的「复制放行命令」，在浏览器里点「复制」就能拿到命令。

1. 打开 dmg，把 **Cavil Loop** 拖进「应用程序」。
2. 双击打开。macOS 会提示无法验证开发者 / 无法打开——点「完成」或「取消」。
3. 任选一种放行方式：
   - **系统设置**：打开「系统设置 → 隐私与安全性」，往下翻到「已阻止使用 Cavil Loop」，点「仍要打开」，输入开机密码，再在弹窗里点「打开」。（macOS 14 及更早也可以在 Finder 里右键 App →「打开」→「打开」。）
   - **终端**：运行下面这行，然后正常双击打开：
     ```bash
     xattr -dr com.apple.quarantine "/Applications/Cavil Loop.app"
     ```
     dmg 窗口里也有一个「复制放行命令」网页：双击用浏览器打开，点「复制」，再到终端粘贴。
4. 之后就和普通 App 一样。从 0.5 起 App 会**自己更新**（见下面「自动更新」），自己更新到的新版本不用再放行；只有手动下载 dmg 装新版本时，才要重新做一次第 3 步。

怎么验证过的：发版流程在 GitHub 的 Mac 机器上，对两个 dmg 都做了：直接启动通过冒烟测试；标上「从网络下载」后 Gatekeeper 确实拒绝；执行上面的终端命令后，用和双击相同的方式（`open`）能正常启动。「系统设置 → 仍要打开」这条路要人点按钮，CI 上没法点，没有自动验证。

### 自动更新

- 什么时候查：每次打开 App 查一次；一直开着的话每 6 小时查一次；设置页「更新」一节可以随时点「立即检查」。一直开着的 App 最长约 6 小时才发现新版，想马上更新就点「立即检查」，或者退出 App 再打开。
- 查到新版就在后台下载、核对签名、换上新版；下载完看板顶部出一条「新版 X 已下载，重启后生效」，点「立即重启」，或者不管它，下次打开 App 就是新版。这条提示点「×」关掉后，这个版本不再提示。
- 只装本仓库正式发布的客户端版本（标签 `client/vX.Y.Z`，不含草稿和预发布），只往高版本走，不降级。每个更新包都带签名，App 只装用发版密钥签过的包；签名对不上就不装，设置页写明「签名校验失败，没有安装」。
- 查不到、下载断了、30 秒没回应、下载中 60 秒收不到数据、换新版失败：都只在设置页「更新」一节写明原因和时间，不弹通知、不在看板上提示；旧版原样不动，下一次检查（6 小时后、下次打开、或手动点）再试。网慢但一直在下的不会被判失败。
- 设置页可以关掉「自动检查更新」：关掉后打开 App 和每 6 小时都不查，只有手动点「立即检查」才查。
- **更新渠道**（设置页「更新」一节）：默认「正式版」，只装上面说的正式版本。选「开发版」后，还会装 main 上每次合并自动发的开发版（版本号像 `0.5.1-dev.387`，Releases 页上标着 Pre-release），能更早用上新改动，但可能不稳定。从开发版切回正式版不会降级，等下一个比当前高的正式版出来自动跟上。开发版只有 Apple 芯片的包，Intel Mac 上这个选项是灰的。正在安装新版时不能切换，装好后可以。
- 怎么验证过的：发版流程在 GitHub 的 Mac 机器上（Apple 芯片和 Intel 各一台），把旧版装进「应用程序」后让它真去检查、下载、换上新版，核对换上的是新版、身上没有「从网络下载」标记、能用和双击相同的方式（`open`）启动；再放一个被改过的更新包，核对它被拒绝、旧版一个字节都没变。CI 机器和你的 Mac 在系统权限上可能不同，第一次真实更新请留意一下。
- 检查更新不用你的 GitHub 登录凭据（仓库是公开的）。下载更新包时 GitHub 会转到它的下载地址（`release-assets.githubusercontent.com` / `objects.githubusercontent.com`），只有更新这件事访问这两个地址。

### 搜索和表格

- 搜索框写法和 GitHub 网页一样；本客户端不支持的写法（搜正文 / 评论、日期比较、自定义字段等）会在黄条里点名并忽略，所以结果可能比网页多，但不会因为一个写错的词变成「0 条」。
- 看板上的黄条都可以点「×」收起；同一个问题只是时间过去不会再弹出，问题变了或恢复后又出现会重新显示，重开 App 后仍存在的问题照常显示。
- 添加 Project 时贴带 `/views/N` 的网址，导入的就是那个视图；不带就导入第一个。导入只在添加时做一次，之后你改的设置一直保留；想重新导入就删掉这个 Project 再加回来。
- 表格的「视图设置」里能改分组、排序、显示的列、左侧按仓库切片、子 issue 缩进。

### 登录

点「用 GitHub 登录」→ App 显示一个短码 → 点「打开 GitHub 授权页」→ 在浏览器里输入短码，点「Authorize」。登录方式默认是「OAuth 应用」，直接用；也可以选「GitHub App（预览）」，但这一版没有内置的 GitHub App，要填你自己建的 App 的 Client ID。两种的区别点选项旁的「两种有什么区别？」看。授权页上列出的权限：OAuth 应用是 `repo`（含代码与设置）、`read:org`、`project`；GitHub App 是那个 App 登记时勾选的权限（可以只给 Issues、Pull requests、Projects，不给代码），以授权页为准。所填 Client ID 和所选方式对不上时不让登录。令牌如果会过期（看应用的设置），App 会在到期前自动续期，你感觉不到。凭据存进 macOS 钥匙串（条目名「Cavil Loop (GitHub)」），下次启动不用再登录；在设置里「退出登录」会同时删掉它。GigleAI 组织如果开了第三方应用限制，第一次授权需要组织管理员批准。

### 提醒（`pending/human`）

- 「待处理」= 所有已加入来源里**开着的** issue / PR（草稿 PR 也算）中带 `pending/human` 的条目；已关闭的 issue、已关闭或已合并的 PR 不算，不论有没有标签。标签名就是设置里「交回 agent」那一节的「等人处理的标签」，两处共用一个设置，要和 daemon 配置里的保持一致（不区分大小写）。
- 某条目上一轮还不是待处理、这一轮是了，就弹一次系统通知；点通知回到 App 并打开那一条的详情。标签摘掉再挂上、或带着标签被重新打开，会再通知一次。同一条目在几个来源里出现，只通知一次、只算一个。
- App 启动后、新加一个来源后、换账号后第一次同步成功时，已经带标签的条目算历史：不弹通知、不弹汇总、不算未读。
- 某个来源这一轮没读全（断网、凭据失效、分页读到一半失败），它这一轮不参与比较：不会冒出「新增」，也不会把条目当成「已移除」。恢复后真正的变化照常通知。
- **Dock 角标只是「未读数」**：窗口不在前台时新挂上 `pending/human` 的开着的条目会让它加一；切到 App（点 Dock 图标、点通知、或直接切到窗口）就清零，已经弹出、还留在通知中心的 Cavil Loop 通知也一并收起。窗口在前台时新来的条目照样弹通知，但不算未读。一条未读的条目在你看之前被摘掉了标签、或被关掉，它就不再算。改设置（标签名、删来源）不会让未读变多。
- 设置页「提醒」一节只写规则、通知被拒时的提示和开机自启开关，不列条目、不显示总数。
- 关掉窗口 App 仍在后台运行（Dock 图标保留），点 Dock 图标回到窗口；完全退出用菜单「退出」或 ⌘Q。设置里可以勾「开机自动启动」，开机启动时不弹窗口。
- 第一次弹通知时，macOS 可能先问是否允许 Cavil Loop 发通知，点「允许」。macOS 拒绝了通知（没允许、或在系统设置里关掉了）时，看板顶部和设置页会显示一条黄色提示，写明去「系统设置 → 通知 → Cavil Loop」打开「允许通知」；角标不受影响。下一条通知成功弹出后，提示自动消失。
- 仓库来源只读开着的、加上最近 14 天有更新的条目（看板来源不受影响，看板里的条目全读）。关闭的条目即使因为刚打了标签而被重新读到，也不提醒；提醒只看开着的条目，所以这个读取范围不影响提醒。
