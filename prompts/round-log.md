# 往返记录（本项目开启了「agent 之间的来回写进同一条评论」）

> 这一段只改一件事：**交给 agent 的评论**怎么发、怎么读。其余一律以上文为准。

一段 agent 之间的来回（worker 交方案 / 交 PR → 复审打回 → worker 修订 → ……）只占一条「往返记录」评论：每次交付在末尾追加一节，只写**这一版改了什么**、**给下一个 agent 的必要交代**和**本轮用量 footer**；完整版本放在记录顶部，换成最新的。这条记录只由 agent 写、只由 agent 改，不改任何人的评论。

## 哪些评论进记录

- **进**：发完要翻到 `@@LABEL_PENDING_REVIEW@@`（交复审）或 `@@LABEL_PENDING_AGENT@@`（复审打回、交回 worker）的那一条评论
- **不进，照上文单独发**：交给人的评论（翻 `@@LABEL_PENDING_HUMAN@@`）、复审通过并翻 `@@LABEL_PENDING_MERGE@@` 的结论（daemon 合并前只认派复审之后新建的评论）、等前置登记、转 PR 跟踪、发现可疑内容的告警

## 怎么发（代替上文那一步的 `gh issue comment` / `gh pr comment`）

1. 把**本节正文**写进一个文件：这一版改了什么（worker）或复审意见（复审，第一行照旧是轮次标记），加上给下一个 agent 的交代；用量 footer 照上文生成，用带 footer 的那个文件。**不要**再把整份方案 / 整份说明贴进本节
2. worker 另把**完整版本**写进一个文件：方案阶段是整份最新方案；PR 阶段是这一版完整的交付说明（不含用量 footer）。复审不用给
3. 运行（`<编号>` 是这条评论要发到的 issue / PR）。发到 PR 上时**必须**带本次交付开始时确认的两样：`--basis` = 本次交付依据的提交（worker：推送后的 `git rev-parse HEAD`；复审：所审的那个提交），`--base` = 当时确认的目标分支；PR 来自别的仓库时再加 `--source <那个仓库>`。缺了命令拒收：

   ```bash
   @@ROUND_LOG_CMD@@ post <编号> --role worker --to <要翻到的标签> --body <本节文件> --full <完整版本文件> [--basis <提交> --base <目标分支>]
   @@ROUND_LOG_CMD@@ post <编号> --role review --of <读取时标出的值> --to <要翻到的标签> --body <本节文件> [--basis <提交> --base <目标分支>]
   ```

   复审**必须**带 `--of`：值就是开始复审时读取命令在「最新单元」下面标出的那个（`（复审对这次交付发结论时，写入命令带上 --of …）`），原样照抄，不要在发结论前重新读一遍再取。审的过程中 worker 又交了新版本时，命令据它认出这条结论过期了

   所审的交付在哪、`--of` 标成什么、命令怎么处理，只有三种：

   | 所审的交付 | 读取命令标出的 `--of` | 它仍是最新交付时 | 之后又有了新交付时 |
   |---|---|---|---|
   | 往返记录里的一节 | 节编号 | 写入记录，翻标签 | 过期：不发、不翻标签 |
   | 一条单独的评论（开关打开前的旧式交付、单独发的交付） | `comment-<编号>` | 拒收：照上文单独发 | 过期：不发、不翻标签 |
   | 正文本身（线程里还没有任何交付，如首次开 PR 时交付说明只写在 PR 正文里） | `body` | 拒收：照上文单独发 | 过期：不发、不翻标签 |

   PR 上同时照常带 `--basis` / `--base`：审的过程中 PR 有了新提交，同样按过期处理

4. 按最后一行的 `RESULT=` 做（退出码与它一一对应）：

| 结果 | 意思 | 接下来 |
|---|---|---|
| `RESULT=written`（0） | 已写入（追加 / 新开 / 改写不成另起了一条完整的新记录） | 照上文翻标签 |
| `RESULT=expired`（3） | 目标已不归这次派工（关了、合并了、换了分支或来源、有了新提交、人已接手），或复审所审的那一版之后又有了新的交付 | 什么都没写；不翻标签，**也不改成单独发**，停下 |
| `RESULT=unknown`（4） | 目标状态读不到 | 什么都没写；不翻标签，停下 |
| `RESULT=unreadable`（5） | 评论读不全，或评论区里已有的往返记录读不懂（缺标记、版本对不上） | 什么都没写；照上文读评论失败的规则处理，**不改成单独发**、不翻标签 |
| `RESULT=failed`（6） | 该写的写不进去 | 照上文发评论失败的做法处理 |
| `RESULT=rejected`（2） | 这条不该进记录（交合并、交人、所审的交付不在记录里），或正文里有记录标记 | 什么都没写；照上文单独发 |
| `RESULT=usage`（64） | 用法不对，包括发到 PR 上没给 `--basis` / `--base`、复审没给 `--of` | 什么都没写；补齐参数重跑。**不要**改成单独发；补不齐就不发评论、不翻标签，停下 |

## 怎么读「最新一条」

上文凡是「读最新评论」「看最新一条是不是复审结论」，一律看这条命令输出里的**最新单元**：

```bash
@@READ_CMD@@
```

- 输出把评论区按「单元」排好：普通评论一条一个，往返记录每节一个；最新单元之后附着它对应的**完整版本**（worker 交付的那一版，或复审所审的那一版）。判断「最新一条带复审轮次标记就改方案」等规则时，最新单元的全文就以那个标记开头
- 输出说「版本对不上」或读不全：照上文读评论失败的规则处理，不按半份内容判断
- 复审数轮次：规则不变，仍是「最近一次人工动作之后本目标第几轮」，重置点照上文的办法定（分页读评论、评论的编辑信息和 issue events，只认派工账号以外的动作）。输出末尾「复审轮次的材料」按时间列出算作一轮复审的单元（往返记录里的复审节，或 loop 账号单独发、第一个非空行整行就是轮次标记的评论；正文里举的例子、半截写法不算）和不是 loop 账号写的评论（带作者，可能是重置点），同一节在评论区出现两次只列一次；那里的总数是**全部历史**，不是当前轮次——只数重置点之后的带标记单元。只改了标签、编辑了评论这类动作不在这份材料里，必须另外查
