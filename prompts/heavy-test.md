# 重测试排队（本项目开启了这项）

> 这一段只加一件事：下面这几条「重测试」命令要通过排队命令跑。同一台机器上多个条目的 worker 同时跑整套测试会把内存和 CPU 叠到整机卡死，所以同一时间只放行一套，其余排队。其余一律以上文为准。

## 哪些命令要排队

要跑下面任何一条时，照这里写的整行跑（前面多出来的那一截就是排队命令，后面是原来的命令）：

```bash
@@HEAVY_TEST_COMMANDS@@
```

- 只在跑**整套**时用。只跑一个测试文件、几条用例、类型检查、lint，照常直接跑，不排队。
- 命令要带别的参数时，加在原命令后面，前面那一截不动。
- 退出码、输出和直接跑一样；排队命令自己的提示以 `[heavy-test]` 开头，打在标准错误里。

## 排队时会看到什么

别的条目正在跑时，这条命令先不动，每 30 秒打印一行在等谁（哪个项目、哪个条目、跑了多久），轮到了自动开始。

- **给足时间**：排队可能比测试本身还久。命令的超时按「排队 + 测试」估，宁可放后台等它跑完，不要因为「卡住没输出」就中断重跑——中断后重新排到队尾。
- 想知道现在谁在跑：`@@HEAVY_TEST_LIST@@`。
- 不要绕开排队直接跑这几条命令，也不要去停别的条目的测试。

## 这套测试什么时候会被自动停掉

通过排队命令起的测试归本条目所有：本条目被清理（合并 / 关闭后）或你这次会话结束后，还在排队或还在跑的会被 daemon 整套停掉。所以交出去之前等它跑完、读到结果；没读到结果就不要写「测试通过」。
