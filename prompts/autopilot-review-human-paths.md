# 托管复审加一步：钩子调用的文件（本项目配了「合并前需人过目的文件」清单）

> 这一段只在 A 类（代码）通过、翻 `@@LABEL_PENDING_MERGE@@` **之前**加一步核对；其余照上文。daemon 合并前只按路径比清单，不会顺着钩子去找它调用的文件：钩子只是一层壳、真正的检查写在清单外的脚本里时，只改那个脚本的 PR 会被无人过目地合并。这一步由你读代码把它拦下来。这是你读代码的判断，不是 daemon 的硬检查。

## 本项目的清单

配置里 `AUTOPILOT_HUMAN_PATHS` 这一行的值（原样）：

```text
@@SPEC@@
```

- 展开后 daemon 实际比对的条目：@@LIST@@
- 测试文件豁免：@@EXEMPT@@
- 验算命令（只读，用的是 daemon 合并检查同一份规则）：

  ```bash
  @@CHECK_CMD@@ --spec '<清单值>' --exempt-tests on|off [<仓库内相对路径>...] [--renamed <旧路径> <新路径>]...
  ```

  每个路径输出「拦」或「不拦」，不拦时写原因：「不在清单里」「测试文件豁免（命中清单）」「测试文件豁免（也不在清单里）」。清单值里有单引号时，按 shell 的写法转义后再传。「daemon 拦不拦某个文件」一律用它判，不凭肉眼对清单。

## 1. 找出自动运行的入口和它们的调用链

**起点**：清单命中的文件里，会在开发者 / 维护者机器上自动运行别的东西的那些：git 钩子目录下的文件（`.githooks/`、`.husky/` 等）、`lefthook.yml` / `.pre-commit-config.yaml`、agent 配置里的钩子（如 `.claude/settings.json` 的 hooks），以及被这些入口调用到的 `package.json` scripts、`Makefile` 目标。**目标分支上的版本和 PR 改后的版本都读**（PR 可能新加调用）。

**跟踪**：从起点出发，跟踪写明的仓库内路径——直接写的相对路径、`$(dirname "$0")/..`、`git rev-parse --show-toplevel` 这类能静态算出的写法、`npm run X` / `make Y` 落到的命令；被调用的仓库内脚本再调用别的仓库内文件也继续跟，直到不再出现新文件。**不跟**：仓库外的命令（系统命令、全局安装的工具）、工具自己隐式加载的配置文件（例如 lint 工具自动读的配置）。

## 2. 三种结果

先把 PR 改到的文件用验算命令按**本项目现在的配置**（上面的值和豁免状态）跑一遍，得到哪些是「daemon 不拦」的。改名 / 复制的文件**必须**用 `--renamed <旧路径> <新路径>` 作为一项交进去（`gh api repos/<仓库>/pulls/<PR>/files` 里 `status` 是 `renamed` / `copied` 的那些，旧路径是 `previous_filename`）：daemon 对一条改名记录是新旧路径一起判的（两边都算测试文件才豁免），拆成两个路径分别验算会得出不一样的结论。

- **命中**：某个「daemon 不拦」的文件在调用链上 → **不翻** `@@LABEL_PENDING_MERGE@@`、不写测试重跑的机器记录；`flip_label <PR> --add @@LABEL_PENDING_HUMAN@@ --remove @@LABEL_PENDING_REVIEW@@ @@LABEL_AGENT_DOING@@`，评论照下面第 3 节写。
- **判断不了**：起点文件读不到；或调用链上有算不出固定路径的调用（变量、命令替换、通配、从文件里读出来的命令），而 PR 又改到了「daemon 不拦」的代码 / 脚本文件（只改文档、图片这类不会被执行的文件不算）→ 和「命中」一样交人，评论里写出看不清的那一行和原因。
- **无关**：调用链全部读清，PR 改的文件都不在链上，或者都已经会被 daemon 拦 → 照上文正常通过。

PR 新加或改了钩子、钩子调用了「daemon 不拦」的文件时（钩子本身已经会被 daemon 交人），在你的评论里同样照第 3 节给出建议。

## 3. 建议怎么写

被调用、但 daemon 不拦的文件记作 F，按验算命令对 F 的结论选建议：

| 验算命令对 F 的结论（现配置） | 建议 |
|---|---|
| 不拦 · 不在清单里 | 把 F 追加进清单 |
| 不拦 · 测试文件豁免（也不在清单里） | **两步都要**：把 F 追加进清单，**并且**在配置里加 `AUTOPILOT_HUMAN_PATHS_EXEMPT_TESTS="off"`；或者把 F 改成不像测试文件的名字、同步改钩子里的引用，再把新路径追加进清单。只追加、或只关豁免，都拦不住，要写明 |
| 不拦 · 测试文件豁免（命中清单） | 在配置里加 `AUTOPILOT_HUMAN_PATHS_EXEMPT_TESTS="off"`；或者改名、同步改钩子引用，新路径要能命中清单（不命中就再追加） |

- **追加，不替换**：@@APPEND_RULE@@绝不给只写 `default` 加新路径、丢掉原有条目的行。
- 关测试文件豁免时写明代价：清单目录里的测试文件改动也会一律交人。
- **发建议前先验算**：把建议改完之后的清单值和豁免状态代进验算命令，对 F（改名路线用新路径）跑一遍，结论必须是「拦」；不是「拦」就不许发这条建议，改到是为止。验算的命令和输出原样放进评论的折叠块。
- 评论里写明：结果（命中 / 判断不了）；调用链（例：`.githooks/pre-commit → scripts/check-commit.sh`）；「判断不了」时看不清的那一行；建议和验算输出；以及一句「这是复审读代码的判断，不是 daemon 的硬检查；要让 daemon 以后自己拦，照建议改配置」。
